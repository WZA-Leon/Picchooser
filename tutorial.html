Picchooser 筛片工具使用教程

基于 EXIF 拍摄时间，自动把照片归类为「连拍 / 孤立照片 / 无拍摄信息」三类，帮你快速清理和归档。

1功能特性

  • 批量扫描：自动扫描源目录下所有受支持的图片（默认 JPEG 系列）。
  • 读取拍摄时间：通过 exifread 解析图片的 EXIF DateTimeOriginal 信息。
  • 连拍识别：拍摄间隔小于阈值（burst_threshold）的照片识别为一组连拍，归入以 burst_folder_prefix 命名的文件夹。
  • 孤立照片识别：与相邻照片时间间隔较大的单张照片，归入 single_folder_name 文件夹。
  • 无 EXIF 处理：没有拍摄时间信息的图片，统一归入 no_exif_folder_name 文件夹。
  • 配置驱动：源目录、阈值、文件夹命名等全部通过 photo_config.json 配置，无需改代码。
  • 运行时可选：启动时选择复制或移动方式整理照片，还可直接修改配置或切换目录，一次分类结束后自动返回主菜单。
  • 彩色控制台菜单：主菜单、目录切换等界面用颜色区分不同类型项，一目了然。
  • 纯 Python 实现：轻量、跨平台。

2快速开始

环境要求

Python 3.8 或更高版本；推荐使用 uv 管理依赖与虚拟环境。

克隆项目

git clone https://github.com/WZA-Leon/Picchooser.git
cd Picchooser

安装依赖（uv）

uv sync

该命令会按 pyproject.toml 创建 .venv 并安装运行依赖（exifread）与开发依赖（pyinstaller）。

不使用 uv 也可以：pip install exifread

运行

uv run python Picchooser.py

安装后直接使用 推荐

使用安装包安装时，安装程序已自动把 picc 命令写入系统环境变量（PATH）。安装完成后，无需进入程序目录，在任意文件夹下打开终端直接输入：

picc
工作目录 = 调用目录。程序以你执行 picc 时所在的当前目录作为工作目录， 因此会读取该目录下的 photo_config.json，并默认把该目录作为待整理的源目录。 想整理哪个文件夹的照片，就 cd 到那个文件夹再运行 picc 即可。

例如，要整理 E:\R6照片备份\100CANON 里的照片：

cd E:\R6照片备份\100CANON
picc
若提示 'picc' 不是内部或外部命令，说明环境变量尚未生效：请重新打开一个终端窗口（或重启资源管理器 / 注销重登）后再试。

3配置说明

编辑项目根目录下的 photo_config.json：

{
  "source_folder": ".",
  "dest_folder": null,
  "copy_mode": true,
  "burst_threshold": 3,
  "supported_ext": [".jpg", ".jpeg", ".JPG", ".JPEG"],
  "burst_folder_prefix": "连拍",
  "single_folder_name": "孤立的照片",
  "no_exif_folder_name": "无拍摄信息"
}
字段类型说明
source_folderstring待整理的源目录，默认为当前目录 .
dest_folderstring | null整理后的输出目录；为 null 时在源目录内生成分类文件夹
copy_modebool默认处理方式的建议值：true 复制原图（保留原图），false 移动原图。启动时仍会询问
burst_thresholdint连拍判定阈值（秒）。两张照片拍摄间隔 ≤ 该值即视为同一组连拍
supported_extarray需要处理的图片扩展名列表
burst_folder_prefixstring连拍文件夹的命名前缀
single_folder_namestring孤立照片的文件夹名
no_exif_folder_namestring无拍摄信息照片的文件夹名

  • 1 复制 / 2 移动：开始扫描源目录并完成分类整理；直接回车采用配置里的 copy_mode 默认值。
  • 3 修改配置：进入配置编辑菜单，逐项修改并自动写回 photo_config.json。

  • 5 软件教程：显示使用说明与当前配置
  • 6 精细筛片：在粗略地根据时间筛片结束后，快速根据内容筛片

6工作原理

  • 遍历 source_folder 中所有扩展名在 supported_ext 内的图片。
  • 读取每张图片的 EXIF 拍摄时间 DateTimeOriginal：读取失败 → 归入 no_exif_folder_name；读取成功 → 按拍摄时间排序。
  • 比较相邻照片的拍摄间隔：间隔 ≤ burst_threshold 秒 → 判定为连拍，归入 burst_folder_prefix 命名的文件夹；间隔较大、孤立出现 → 归入 single_folder_name。
  • 根据运行时选择的处理方式，把照片复制或移动到 dest_folder（或源目录下的分类文件夹）。

8常见问题

Q：为什么有些照片被判为「无拍摄信息」？

A：图片缺少 EXIF 数据（如经过压缩、截图、社交软件转发），或 EXIF 中没有 DateTimeOriginal 字段。

Q：burst_threshold 设多少合适？

A：连拍通常是每秒数张，建议设为 1~3 秒；若想更宽松地合并相册，可适当调大。

Q：会修改我的原始照片吗？

A：选择复制模式时原图不动，只是在分类文件夹里生成一份副本（会占用额外磁盘空间）；选择移动模式时原图会被移到分类文件夹，源目录不再保留，请谨慎使用。

Q：复制和移动该怎么选？

A：想保留原图、且磁盘空间充足时选复制；想直接整理归档、不保留原图时选移动。启动时按提示输入 1（复制）或 2（移动）即可，直接回车采用配置里的默认值。

Q：分类完成后程序就退出了吗？

A：不会。每次分类结束后会等待你按回车，然后自动返回主菜单，可以继续对其它目录分类、修改配置或切换目录，直到在主菜单输入 0 才退出。

Q：怎么在不编辑 JSON 的情况下改配置 / 换目录？

A：在主菜单选择 3 修改配置，会列出所有可编辑字段及当前值，按序号逐项修改并自动保存；选择 4 切换目录，则进入「选择文件夹」菜单选好目录，切换结果同样会写回 photo_config.json，下次启动自动生效。

Q：支持哪些图片格式？能处理 RAW / HEIC / PNG 吗？

A：默认只处理 supported_ext 中列出的扩展名（默认 .jpg / .jpeg / .JPG / .JPEG）。想处理其它格式，把对应扩展名加进 supported_ext 即可；但能否读到拍摄时间取决于该格式是否含可解析的 EXIF，RAW / HEIC 等可能读不到而落入「无拍摄信息」。

Q：照片会按拍摄日期自动分到「年 / 月 / 日」文件夹吗？

A：不会。本工具只按「连拍 / 孤立照片 / 无拍摄信息」三类归档，不按日期建目录。若需要按日期归档，可在分类完成后自行处理，或修改源码扩展该逻辑。

Q：连拍文件夹会生成多个吗？命名规则是什么？

A：会。每一组连拍会生成一个以 burst_folder_prefix 为前缀的独立文件夹（如「连拍」「连拍_2」等），互不混淆；孤立照片和无拍摄信息则分别汇总到各自命名的单个文件夹中。

Q：目标目录里已有同名文件会怎样？会被覆盖吗？

A：程序在写入前会检查目标路径，遇到同名文件会自动重命名（追加序号）以避免覆盖已有照片，请放心使用。

Q：处理大量照片时很慢 / 卡住，怎么办？

A：读取 EXIF 是逐张进行的，照片数量多时耗时属正常。建议分批处理，或先只整理单个子目录；移动模式通常比复制模式快（复制需实际写入数据）。

Q：为什么提示「无支持图片」？

A：说明该目录（及其子目录）内没有扩展名在 supported_ext 中的图片。请确认照片格式是否受支持，或把对应扩展名加入配置。

Q：photo_config.json 被我改坏了 / 删掉了怎么办？

A：程序在配置缺失或字段非法时会使用内置默认值，并在必要时重新生成配置文件。若想恢复默认，直接删除 photo_config.json 后重新运行即可。

Q：能在 macOS / Linux 上运行吗？

A：可以。程序为纯 Python 实现，跨平台；但安装包（picc 命令写入 PATH）目前主要面向 Windows，其它系统请用 uv run python Picchooser.py 运行。

Q：整理后想撤销 / 恢复原状怎么办？

A：程序不提供一键撤销。建议首次使用时选择复制模式，原图保持不动，确认结果满意后再手动清理；若用了移动模式，请从分类文件夹里把照片移回原目录。

Q：如何反馈 Bug 或提建议？

A：欢迎到 GitHub Issues 提交，请附上操作系统、照片格式、报错信息及复现步骤，便于快速定位。

9打包与分发

项目使用 PyInstaller 打包为单文件 exe，配置为 Picchooser.spec：

uv run pyinstaller Picchooser.spec --noconfirm --clean

产物：dist/picc.exe，单文件、免安装、无需 Python 环境。

安装包会把 picc 写入系统环境变量（PATH），安装后在任意目录直接输入 picc 即可运行，且以当前调用目录作为工作目录。把 photo_config.json 放在调用目录（或与 exe 相同的目录）即可使用。
